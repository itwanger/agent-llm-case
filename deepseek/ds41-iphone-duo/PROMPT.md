你是一名擅长高保真网页复刻的前端工程师，同时具备视觉设计和交互动效能力。

请实际编写代码，复刻下面的 Apple iPhone Duo 产品官网，交付可以在本地运行、浏览和交互的完整网页：

https://www.apple.com.cn/iphone-duo/

目标是尽可能还原该页面的视觉构图、产品素材、排版节奏、页面结构和核心交互。不要只提供实现方案，也不要只完成首屏。

一、先观察参考页面

如果环境支持联网或浏览器操作，请先打开参考网址，完成以下准备：

1. 从顶部到底部观察页面，记录各区域的顺序、尺寸关系、背景颜色、文字排版和图片构图。
2. 分别观察桌面和手机宽度下的布局。
3. 检查导航、配色切换、产品姿态切换、折叠滑块、轮播、弹层、FAQ 等交互。
4. 从 HTML、picture/srcset、CSS 背景和 video/source 中寻找实际使用的图片与视频资源。
5. 对滚动后仍未加载的区域，结合 DOM 和资源判断，不能把暂时空白当作原设计。

如果无法访问参考网址，请明确说明限制，并依据下面给出的页面结构继续实现，不要声称已经浏览或验证过原站。

二、技术要求

- 若当前目录已有前端项目，沿用其技术栈和运行方式。
- 若为空目录，使用 React + TypeScript + Vite。
- 样式可使用 CSS Modules、普通 CSS 或项目已有的 Tailwind CSS。
- 优先使用 CSS、IntersectionObserver、requestAnimationFrame 完成动画；复杂滚动效果按需使用 GSAP。
- 页面拆分为清晰的组件，产品参数、轮播内容、FAQ 和资源地址独立管理。
- 不通过 iframe 嵌入原站，不把整页截图当作页面实现。
- 不直接加载原站整套运行脚本来冒充复刻。
- 保留当前目录已有的用户文件。

三、视觉原则

请以参考页面为最终依据，以下是实现起点：

1. 整体以纯白和浅灰背景为主，深灰正文、蓝色操作按钮。
2. 使用大幅真实产品图、宽阔留白、醒目标题和克制的正文。
3. 不添加参考页面中不存在的霓虹光效、紫色渐变、复杂阴影或装饰性图案。
4. 避免把所有内容都排成同一种三列卡片。根据原站使用全宽图片、横向画廊、居中产品展示、图文组合和参数布局。
5. 参考色：
   - 主文字：#1d1d1f
   - 次级文字：#6e6e73
   - 浅灰背景：#f5f5f7
   - 页面背景：#ffffff
   - 按钮蓝：#0071e3
   实际取值以原站为准。
6. 字体优先使用系统字体：
   -apple-system, BlinkMacSystemFont, "SF Pro Display",
   "SF Pro Text", "PingFang SC", "Helvetica Neue", sans-serif
7. 建立统一的字号、间距、圆角和内容宽度变量。桌面主标题可从 72–96px 起调，章节标题可从 48–64px 起调，移动端使用 clamp() 合理缩放。
8. 保留中文标题的自然断行和原站视觉重心，避免孤立标点、过长正文和生硬换行。
9. 产品本身是视觉中心。优先校准图片大小、位置、留白和标题比例，再打磨细小装饰。

六、交互和动画

- 先确保静态页面完整，再逐步增强动画。
- 文字和图片进入视口时可使用轻微上移与淡入。
- 悬停、按钮、标签切换动画保持短促克制。
- 不强制劫持整页滚动。
- 如使用 sticky 滚动展示，应正确计算开始、结束和释放位置。
- 不让正文依赖动画成功才能显示，脚本或资源失败时也能阅读。
- 支持 prefers-reduced-motion。
- 弹层支持 Escape 关闭、焦点约束和关闭后恢复焦点。
- 价格或购买入口使用从原站核实的目标地址，或打开清楚标注的本地演示弹层。
- 不使用无意义的 href="#" 或 alert() 代替正常交互。
- 所有按钮和标签都应有明确反馈，包括悬停、按下、选中和禁用状态。

七、响应式与性能

至少检查以下尺寸：1440 × 900、1024 × 768、390 × 844。

要求：

- 手机端重新组织布局，而不是把桌面版整体缩小。
- 标题、正文和按钮不重叠、不截断。
- 图片有明确尺寸或 aspect-ratio，减少布局跳动。
- 首屏关键图片优先加载，下面的图片按需懒加载。
- 不一次下载所有大尺寸视频或全部动画帧。
- 控制滚动监听和重绘开销。
- 轮播、滑块在触摸设备上可正常操作。
- 图标有可访问名称，交互控件有清晰焦点状态。
- 固定导航不会遮挡锚点标题。
- 页面缩放、窗口尺寸变化后，滚动动画和产品布局仍然正确。

八、实现顺序与验收

请按以下顺序实际执行：

1. 查看参考页，整理区域和素材。
2. 建立页面骨架与视觉变量。
3. 完成首屏，先校准标题、产品尺寸、导航和留白。
4. 完成所有后续章节及响应式布局。
5. 加入核心交互和动效。
6. 启动本地服务，进行浏览器检查。
7. 执行生产构建，修复报错。
8. 对照参考页面截图，修正明显视觉差异。

重点验收：

- 第一眼能辨认出是该 iPhone Duo 页面。
- 首屏构图和真实产品素材正确。
- 整页章节完整，没有后半段空壳。
- 颜色切换、产品姿态、滑块、轮播、FAQ、弹层能够实际操作。
- 没有破图、永久加载状态、明显横向溢出或遮挡。
- 控制台没有影响页面使用的错误。
- 构建成功。

如果需要取舍，优先保证：真实产品素材、首屏构图、整页完整性、排版比例、核心交互、响应式适配，最后再增加复杂动画。
