# 《暴力摩托》核心原型开发提示词

你是一名擅长 Three.js、街机驾驶手感和游戏交互的开发者。请在当前工作区的 `RoadRash` 目录内，实现一个可以直接在浏览器游玩的 3D 摩托竞速格斗原型，灵感来自 90 年代《暴力摩托》。请直接编写、运行和验证项目，不要只输出设计方案或静态演示。

## 一、目标与技术要求

- 使用 Three.js + TypeScript + Vite，桌面浏览器键盘操作。
- 采用低多边形 3D 美术、鲜明配色和复古街机 HUD；使用程序化几何体生成摩托、骑手、汽车、道路和场景，保证没有外部模型也能完整游玩。
- 实现一场约 2～3 分钟的单人比赛，包含玩家和 5 名 AI 车手，以及独立的对向汽车交通。
- 核心体验是“高速驾驶 → 与对手并行 → 格斗超车 → 躲避车辆 → 冲向终点”。驾驶、战斗、摔车和比赛结算必须组成完整可玩流程。
- 优先保证操作响应、打击反馈和稳定运行。物理采用容易调校的街机近似，不要求完整刚体模拟，也不要求联机、账号、商店或复杂资源系统。

## 二、公路、驾驶与镜头

- 构建一条连续的双向双车道公路，包含左右弯、连续弯和缓坡起伏；明确区分本车道与对向车道，用中心线、路肩、护栏、树木和路牌提供速度参照。
- 道路必须真正改变空间方向与高度，不能用直路配合背景摆动伪装弯道。
- 建议采用沿道路的纵向进度与横向偏移管理车辆位置，并由道路局部坐标转换到世界坐标，统一处理弯道、坡度、碰撞和排名。
- 支持加速、制动、左右转向；具有加速度、极速、转向惯性和松油门后的减速。高速过弯更困难，驶入路肩会明显减速。
- 摩托和骑手应随转向产生可见的压弯倾角（Roll），倾角与速度、转弯强度相关，并平滑回正。倾斜围绕车辆前进方向发生，避免模型在世界坐标中错误旋转。
- 使用第三人称追尾镜头，平滑跟随玩家；根据速度适度调整视野和跟随距离。镜头保持可读的地平线，不与车身等幅倾斜。

## 三、格斗系统与 AI

- `J`：向左挥拳，只攻击左侧近距离对手。
- `K`：向右挥拳，只攻击右侧近距离对手。
- `L`：挥动短棍，攻击距离稍长、伤害更高、冷却更久；优先攻击最近的有效对手，并通过动作显示挥击方向。
- 攻击应有起手、有效命中窗口和收招，具有明确的距离、侧向范围与冷却；一次挥击对同一目标最多造成一次伤害。长按不能绕过冷却。
- 命中时同时提供挥击动作、受击偏移、短暂闪色或粒子、打击音效；玩家命中或受击时加入轻微且短暂的镜头震动。
- 每名车手有血量与短暂受击保护。普通攻击连续命中约 3～5 次可以击倒对手，具体数值集中配置。
- AI 能沿公路驾驶、调整速度、尝试超车与避障；接近玩家后会进入“靠近 → 并排行驶 → 挑衅提示 → 攻击 → 拉开距离”的状态流程。
- AI 攻击要有预兆、距离限制和冷却，不能隔空命中或瞬间贴近。限制同时主动围攻的数量，给玩家反应空间。
- 被击倒的对手会摔车并失去比赛进度，延迟后可重新上车继续比赛。

## 四、碰撞、避障与摔车

- 对向车道持续出现逆向行驶的汽车，车辆沿道路方向运动，具有足够的可见预警距离；生成时避开玩家附近，禁止突然刷在玩家面前。
- 区分轻微擦碰与严重撞击：擦碰造成减速和横向扰动；高速正面碰撞或血量耗尽触发摔车。
- 撞击判定考虑相对速度；通过固定时间步、子步或扫掠检测，避免高速穿透汽车。
- 摔车时骑手与摩托分离：骑手带有向前抛出、落地与地面滑行表现，摩托侧翻滑行，并配合撞击音效、火花和速度损失。
- 摔车后镜头短暂跟随骑手，约 2～3 秒后在附近安全位置恢复比赛；重置为低速、恢复可继续比赛的血量，并给予短暂无碰撞保护，避免反复被撞。
- 玩家与 AI 共用一致的碰撞和摔车规则。

## 五、操作与复古 HUD

| 按键 | 功能 |
| --- | --- |
| W / ↑ | 加速 |
| S / ↓ | 制动 |
| A / ←、D / → | 左右转向 |
| J / K | 左拳 / 右拳 |
| L | 挥动武器 |
| Esc | 暂停 / 继续 |
| R | 比赛结束后重新开始 |

- HUD 展示速度（km/h）、玩家血条、实时排名（例如 `3 / 6`）、比赛进度、计时和武器冷却；附近对手显示简洁血条或命中反馈。
- 采用像素风文字、粗边框、高对比配色，可加入适度扫描线效果，但不能遮挡道路或影响辨识。
- 排名必须基于玩家与 AI 的真实赛道进度计算；速度、血量、进度和冷却必须绑定实际游戏状态。
- 提供开始界面与操作说明、倒计时、暂停界面、终点结算界面，展示最终名次和用时，并支持重新开始。
- 使用 Web Audio 或本地音频实现随转速变化的引擎声、挥击、命中、撞击和 UI 音效；在玩家点击开始后解锁音频，提供静音按钮。

## 六、工程与实现顺序

- 清晰拆分道路、驾驶、AI、战斗、碰撞、音效、HUD 和比赛状态模块，避免全部逻辑堆在单个文件。
- 将速度、操控、伤害、冷却、AI 攻击频率和恢复时间集中到配置中。
- 游戏逻辑不依赖显示帧率；暂停和浏览器失焦时暂停模拟，并清理按键状态，恢复时避免时间跨度导致瞬移。
- 控制几何体、材质与粒子数量，复用重复物体，限制像素比；以普通桌面浏览器接近 60 FPS 为优化目标，未经测量不要声称达到目标。
- 按“道路与驾驶 → AI 竞速 → 格斗 → 碰撞与摔车 → HUD、音效与结算”的顺序实现，但最终交付必须覆盖全部核心机制。
- 若实现细节没有明确指定，自行选择合理默认值并继续，不要因非关键美术或参数问题中断开发。

## 七、验收与交付

必须实际启动项目并检查以下完整流程：

1. 执行 `npm install`、`npm run dev` 可以启动；`npm run build` 成功。
2. 开始比赛后可以驾驶，明显看到弯道、坡度、压弯倾斜和速度变化。
3. `J`、`K`、`L` 有不同动作及有效攻击范围；命中时扣血并播放音效，连续命中可使对手摔车。
4. AI 可以超车、靠近和攻击玩家，不能仅作为沿固定轨迹移动的摆设。
5. 能遭遇对向汽车；撞击后骑手被甩出滑行，之后恢复比赛。
6. HUD 随实际状态更新，抵达终点后可以结算并重开；重开不会叠加事件监听、音效或旧车辆。
7. 检查浏览器控制台错误，并记录实际验证方式；无法执行的检查要明确说明，不能写成已通过。
