# ROAD RASH 3D PROTO

致敬 90 年代《暴力摩托》的 3D 摩托竞速格斗原型。Three.js + TypeScript + Vite，全程序化几何体与运行时 Canvas 程序化贴图（无外部模型/贴图文件），桌面浏览器键盘操作，单场比赛约 2～3 分钟。

## 启动

```bash
npm install
npm run dev      # 开发服务器，默认 http://localhost:5173
npm run build    # tsc 类型检查 + 生产构建（dist/）
npm run preview  # 预览生产构建
```

打开页面后点击 **START ENGINE**（或按 Enter）开始比赛；音频在首次点击后解锁。

## 操作

| 按键 | 功能 |
| --- | --- |
| W / ↑ | 加速 |
| S / ↓ | 制动 |
| A / ← 、D / → | 左右转向（速度越高越需要主动压弯对抗离心漂移） |
| J | 左拳（仅左侧近距离目标） |
| K | 右拳（仅右侧近距离目标） |
| L | 挥棍（距离更长、伤害更高、冷却更久，自动选最近有效目标） |
| Esc | 暂停 / 继续（浏览器失焦自动暂停） |
| M | 静音开关（右上角按钮同） |
| R | 结算后重新开始 |

## 核心机制

- **道路**：5.2km 双向四车道（本方向两车道 + 对向两车道）公路，由曲率/坡度分段积分生成，含左右弯、连续 S 弯与起伏坡；车辆位置用「纵向进度 s + 横向偏移 t」管理，经道路局部坐标架转世界坐标，弯道/坡度/碰撞/排名共用同一套坐标。横向约定为右手系、右侧通行：+t 为行进方向右侧（本方向车道 t>0，对向车道 t<0），朝向基架满足 x×y=z，模型车头（局部 +Z）始终指向行进方向。
- **驾驶**：加速度、极速、制动、松油门滑行阻力；路肩强减速；弯道离心漂移需转向对抗；压弯 Roll 围绕车辆前进轴，随速度与转向平滑变化；追尾镜头随速度调整距离与 FOV，不随车身倾斜。
- **格斗**：攻击含起手/有效窗口/收招与冷却（长按不连发，一次挥击对同一目标只结算一次）；命中有受击偏移、闪白、粒子、音效与镜头震动；血量归零即摔车。
- **AI**：5 名车手会沿路驾驶、按弯道限速、超车避障；带橡皮筋速度修正保持车群在玩家附近；接近玩家后走「靠近 → 并排 → 挑衅(!) → 预兆挥击 → 拉开」状态机，同时主动围攻者上限 2 人；被击倒后摔车延迟重生。
- **交通与碰撞**：对向车道持续来车（生成点距玩家 ≥350m，不会刷脸）；固定步长 1/60 + 每步 3 子步避免高速穿透；区分擦碰（减速+横推+小额伤害）与高速正面撞击（摔车）；摔车时骑手抛出、弹地、滑行，摩托侧翻冒火花；约 2.6s 后在原地低速恢复并给 3s 无敌保护。
- **比赛流程**：开始界面 → 3-2-1 倒计时 → 比赛 → 终点结算（名次+用时）→ R 重开；排名基于真实赛道进度；重开为状态重置，不重复注册监听/音效/车辆。
- **HUD**：速度 km/h、血条、实时排名 `n / 6`、赛程进度条、计时、拳/棍冷却条；附近对手头顶浮标显示名字+血条，挑衅/出招时红框 `!` 预警；像素风粗边框配色 + 轻度扫描线。
- **音频**：Web Audio 程序化合成——随转速变化的引擎声、路肩擦地声、挥击/命中/撞击/倒计时/结算/UI 音效。
- **渲染/视觉**：ACES Filmic 色调映射 + PCF 软阴影（平行光正交阴影相机跟随玩家，2048 阴影图）；渐变天空球 + 球簇云；MeshStandardMaterial 配合运行时 Canvas 程序化贴图（沥青噪点/草地斑点，ribbon 几何带世界尺度 UV）；树冠为多球簇合并几何、路边实例化灌木/花草/岩石；摩托/骑手用胶囊与球体圆角件。

## 调试钩子

`window.__rr` 暴露只读状态与少量测试辅助（`start()`、`placeAIBeside(side)`、`aiAttack()`、`spawnCarAhead()`、`setS(v)`、`hp(i)`、`activeCars()`、`fps`），仅供自动化验证使用，不影响正常游玩。

## 已知限制

- 街机近似物理：无真实刚体/悬挂模拟，碰撞为进度/偏移空间的分段判定。
- AI 之间不互相格斗（只对玩家出手），AI 间仅有推挤碰撞。
- 摔车重生为原地恢复（带无敌帧），不做拖车/裁判流程。
- 视觉为风格化低多边形：单一平行光阴影（紧贴玩家的阴影视锥，远处无阴影）、无 SSAO/反射/后处理辉光；树冠/灌木为 flat-shading 面片感。
- 仅桌面键盘操作，未做移动端触控。
- 生产包约 545KB（gzip 142KB），主要为 three.js 本体，未做代码分割。

## 实测验证记录（Playwright，Chromium）

- `npm install` / `npm run dev` / `npm run build`（含 `tsc --noEmit`）均通过。
- 驾驶：按住 W 速度 0→48 m/s（HUD 160 km/h），s 持续推进；转向改变 t；松油门滑行减速；路肩/护栏边界减速生效；FPS 稳定 ≈60。
- 格斗：定点验证 J 左拳命中左侧目标（-22 HP）、K 不命中左侧（侧向限制）、K 命中右侧、L 棍命中（-38 HP）；长按 J 1.3s 仅一次伤害；冷却内再按无效；目标被击退出范围后不再命中；HP 归零触发摔车并延迟重生（HP 60）。
- AI：正常比赛中观察到完整状态链 approach→taunt→attack→disengage，玩家被 AI 命中掉血；排名在 6↔1 间双向变化（超车与被超车）。
- 交通/摔车：`spawnCarAhead` 后加速迎头相撞触发玩家摔车（骑手分离滑行），2.6s 后恢复比赛（低速 + HP 60 + 3s 无敌）。
- 流程：终点结算显示名次与用时（`YOU FINISHED 1st IN 0:58.4`），R 重开后车辆/计时/进度全部重置；Esc 暂停时计时冻结、恢复继续；静音按钮文案切换正常。
- 控制台：最终运行 0 error 0 warning（早期发现并修复：实例化护栏柱缓冲溢出、路肩死锁、进度条负宽度、favicon 404）。
- 视觉升级后复测：开启阴影/色调映射/程序化贴图后，行驶中 FPS 实测仍为 60（`window.__rr.fps`）；J 左拳仍 -22 HP；截图确认路面/草地贴图、球簇树、云、渐变天空与车底软阴影均正常渲染；控制台 0 error 0 warning。
- 视觉升级中发现并修复：天空 ShaderMaterial 的 `#include` 指令必须行首书写否则片元着色器编译失败；一次错误的坐标架手性修正曾使 ribbon 三角绕序相对 FrontSide 反转，路面/草地/标线从上方被剔除（表现为"地面消失只剩天空色"）——最终通过恢复正确横向约定（right = forward × up，+t = 行进方向右侧）并还原原始绕序修复。
- 横向约定恢复后复测：D 键使 t 增大并贴右护栏（+t = 屏幕右侧），A 键回落；对向来车出现在左半幅、本方向车群在右侧；J 命中左侧目标（-22 HP）、K 不命中左侧、K 命中右侧（-22 HP），格斗侧向判定与通行方向一致；FPS ≈60，控制台 0 error 0 warning。
- 修复"路面穿模"（草地盖住沥青/标线）：根因是草地原本用沿道路展开的 ribbon（横向 ±220 m），在曲率半径小于展开宽度的弯道/发夹弯处网格自我折叠，折回部分正好压在车行道上方。改为世界空间高度场（10 m 网格、chamfer 距离变换 + 反距离加权混合取最近道路行高度 -0.9 m，并在道路 25 m 内钳制不得高于路面），几何上不可能再翻到路面上；s=640/1300/2990/4650 等坡顶与发夹弯定点截图确认路面、标线、路肩完整，行驶中 FPS 60。
- 修复 AI 逆行轨迹：原 `ai.ts` 车道选择把 t<0 的车手默认锁进对向车道（-2.0），导致无超车动作时也长期逆行；现默认车道恒为本向车道，对向车道只作为超车借道（overtakeTimer 3 s 内），且起跑后 4 s 内禁止借道超车，避免发车格立刻散到中线左侧。同时发车格原在 s<0（road mesh 从 s=0 开始），车手站在草地上，已移到 s=10/25 起跑带上。复测 52.5 s 录制：所有车手 raceTime<4 s 内逆行时长为 0，全程逆行仅 ≤3.3 s 的超车借道片段，玩家 t 稳定 3.6–4.2；起跑截图确认六车均在右半幅沥青上。
- 修复车体朝向反转且不随道路转向：`setOrientation` 传给 `makeBasis` 的 (right, up, forward) 是左手三元组（几何右 = forward × up），得到反射矩阵；`setFromRotationMatrix` 将其退化为模长 0.707 的近单位四元数——车体不随道路朝向旋转、恒指世界 +Z（起跑直道行进方向为 -Z，表现为"一直开倒车"），且被缩放一半。现将基的 X 列取几何左使之成为真旋转，摩托非对称部件（排气管、左右臂）x 镜像补偿，左右拳横向摆动符号同步修正；实测直道与弯道（s=760）模型 +Z（车头）与道路 forward 点积均 = 1.000、四元数模长 1，追背视角截图确认看到车尾、排气管在右侧。
- 未验证项：真实音频听感（自动化环境无输出设备，仅验证 AudioContext 节点创建与静音开关）；不同浏览器/显卡兼容性（仅 Chromium 桌面）。
